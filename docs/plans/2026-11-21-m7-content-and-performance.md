### Task 3: Sparse LU backend

**Files:** Create `crates/nodal-engine/src/linalg/sparse.rs`. Modify `crates/nodal-engine/Cargo.toml` (faer features `["linalg", "sparse-linalg"]`), `linalg/mod.rs`, `analysis/newton.rs`, `analysis/ac.rs` (and `tran.rs` if it owns a solver), `docs/ARCHITECTURE.md` (linear solver section), `docs/adr/0003-linear-solver.md` (one "Update (M7)" paragraph with the measurement that triggered it; the decision itself is unchanged). Remove `test.fail()` from `perf.spec.ts`.

**Interfaces:**
- `pub struct SparseLu<T: Scalar = f64>` implementing `LinearSolver<T>` over the same `DenseMatrix<T>` input. `factor` collects the nonzero pattern (column-compressed), reuses the cached faer symbolic LU when the pattern equals the previous one, otherwise recomputes it, then factors numerically. The singular check keeps the dense rule: for each original column k, the pivot of that column (map through faer's column permutation) must exceed `n · ε · max |A[:, k]|`, and `SolveError::SingularPivot { index }` carries the original column index, so error labels are unchanged. Non-finite entries reject as today.
- Newton and AC use `SparseLu`. `DenseLu` stays as the test oracle and is not deleted.

- [ ] **Step 1:** Tests in `sparse.rs`: `matches_dense_on_random_sparse` (seeded 20 random diagonally dominant 30×30 real and complex systems at 10% density: solutions agree to 1e-12 relative), `singular_column_reports_original_index` (zero column 3 of 5 → index 3), `pattern_change_refactors` (factor A, then A with one entry set to 0 and another made nonzero, solve matches dense), `rejects_non_finite`.
