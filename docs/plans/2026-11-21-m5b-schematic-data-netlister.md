# M5b Schematic Data and Netlister Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A schematic drawn in the editor becomes a project that can be edited in a parameter inspector, netlisted into the IR with diagnostics, autosaved in IndexedDB, and exported and imported as `.nodal.json`. Every reference circuit in `validation/circuits/` ships as a generated `.nodal.json` schematic with layout, and CI proves that each one loads and netlists to an IR equivalent to its reference.

**Architecture:** `packages/schema` gains the project file schema (Zod, `formatVersion` 1, migration hook) around the M5a schematic, with a model library and the simulation block. The netlister is a pure function in `apps/web/src/netlist/`: union–find over the M5a connectivity rule, net naming from labels and ground, parameter parsing with the ADR 0009 value notation, then `parseNetlist` as the final gate. The editor store keeps its schematic history and adds the project metadata; an inspector panel, a diagnostics list and a project toolbar sit around the canvas. Autosave is a small IndexedDB wrapper. The reference schematics are authored by agents (not hand-drawn by Tristan) under `validation/schematics/`, one per reference circuit, and an equivalence checker compares their netlists with the reference IR.

**Tech Stack:** unchanged from M5a (TypeScript 6, React 19, Zustand 5, Immer 11, Zod 4, Vitest 5 + jsdom, Playwright). New dev dependency `fake-indexeddb` for tests only.

**Spec:** [`docs/ROADMAP.md`](../ROADMAP.md) §M5b; [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md) §3, §6.1, §6.2, §7; ADRs [0004](../adr/0004-local-first-no-backend.md), [0005](../adr/0005-frontend-stack.md), [0009](../adr/0009-value-notation.md); Tristan's M5 scope notes (2026-11-20): users can save a circuit and load it again; the reference circuits are generated by Claude, ship as `.nodal.json` files with layout that load in the editor, and the M5b exit test is "load each reference circuit, netlist it, compare with the reference IR".

A value is converted by building the decimal string `<mantissa>e<exponent>` and calling `Number()` once, so `10u` is exactly `1e-5`.
- Netlist equivalence compares numbers with `===` and nodes up to a bijective renaming that maps `"0"` to `"0"`.
- Files under ~400 lines; components small.

## Review Focus

1. **Suffix rounding and case** (`10u`, `4.7k`, `1M` vs `1m` vs `1meg`, `2.2µ` with either mu). Expected: `10u === 1e-5`, `1M === 1e6`, `1m === 1e-3`, both mu characters accepted, `1MEG` rejected. Pinned by `suffix_values_are_correctly_rounded` (Task 2).
2. **Labels whose text differs only in case** (`OUT` on one wire, `out` on another). Expected: one net (IR node names are compared ignoring case), named with the first spelling in document order. Pinned by `labels_join_ignoring_case` (Task 3).
3. **A user label named like a generated name** (a label `N001` plus unlabeled nets). Expected: generated names skip every label name, ignoring case. Pinned by `generated_names_skip_labels` (Task 3).
4. **A corrupt, older or future-version autosave at startup.** Expected: the editor starts empty, the status bar reports why, and the stored record is kept under a backup key, not overwritten. Pinned by `corrupt_autosave_is_kept_and_reported` (Task 7).
5. **Renaming a voltage source that a CCVS, CCCS or DC sweep refers to.** Expected: no silent rewrite; the netlister reports `unknown-control-source` (or `unknown-sweep-source`) naming both items. Pinned by `renamed_control_source_reports` (Task 3).

### Task 3: Netlister and netlist equivalence

**Files:** Create `apps/web/src/netlist/{nets,elements,netlister,equivalence}.ts` with tests `nets.test.ts`, `netlister.test.ts`, `equivalence.test.ts`. Modify `docs/ARCHITECTURE.md` §6.2.

**Interfaces:**
- Consumes: `Project` (Task 1); `parseValue`, `parsePwl`, `PARAM_FIELDS`, `paramValue` (Task 2); `pointOnWire` (`editor/model/connectivity.ts`), `pinPositions`, `SYMBOLS`; `parseNetlist`.
- Produces:
  - `type Diagnostic = { severity: "error" | "warning"; code: DiagnosticCode; message: string; itemIds: string[] }`, with `DiagnosticCode` = `"no-ground" | "invalid-value" | "missing-value" | "bad-name" | "duplicate-name" | "bad-label" | "label-conflict" | "missing-model" | "model-type-mismatch" | "invalid-model" | "unknown-control-source" | "unknown-sweep-source" | "shorted-element" | "dangling-pin" | "unconnected-part" | "ir-invalid"`.
  - `nets.ts`: `buildNets(doc: Schematic): { netOfPin: Map<string, string>; diagnostics: Diagnostic[] }` (key `"<partId>:<pinName>"`, value the net name).
  - `netlister.ts`: `projectToNetlist(project: Project): { ir: Netlist | null; diagnostics: Diagnostic[] }`; `ir` is `null` when any error is present.
  - `equivalence.ts`: `compareNetlists(a: Netlist, b: Netlist): string[]` (empty when equivalent; each string names one difference).
- Rules:
  - Union–find over pins, wire points and label anchors. A wire is one conductor. A pin, wire end or label anchor at point `P` joins every pin, wire end and label anchor at `P` and every wire with `pointOnWire(w, P)` (ARCHITECTURE §6.1). Bends and crossings join nothing by themselves.
  - Net names: a ground pin forces `"0"`; a label names its net. Label text must match the IR node-name regex and not be `0` or `gnd` in any case (`bad-label`). Labels on one net that differ ignoring case → `label-conflict`; labels equal ignoring case on different nets join them (Review Focus 2). A label on ground → `label-conflict`. Remaining nets get `N001`, `N002`… in order of first pin (parts in document order, pins in catalog order), skipping label names ignoring case.
  - Elements in part order, ground skipped. Kind letter from the part's `SYMBOLS` prefix (op-amp → `E`). Name: the part name, which must match the IR element regex and start with its kind letter (`bad-name`); the op-amp emits `E` + name, nodes `[out, "0"]`, `controlNodes: [inp, inn]`, `gain`. Duplicate IR names ignoring case → `duplicate-name`. Nodes follow pin order (E, G, S: first two pins → `nodes`, last two → `controlNodes`).
  - Values via `parseValue` (`invalid-value`, or `missing-value` for an empty required field). `acMag` set → `ac: { mag, phase }`. `wave` pulse/sin/pwl → `tran` with the IR field names; optional empty fields are omitted.
  - `model` must name a project model (`missing-model`) of an allowed type (`model-type-mismatch`). Project models → IR models with parsed params (`invalid-model` for a bad value). `controlSource` must name a vsource part (`unknown-control-source`). A DC analysis `source` must name a vsource or isource part (`unknown-sweep-source`).
  - A two-terminal element with both pins on one net → `shorted-element`. No ground pin anywhere → `no-ground`. Warnings: a pin alone on its net → `dangling-pin`; a part with every pin alone → `unconnected-part` (instead of its dangling pins).
  - `title` = project name; `analyses`, `options` from `project.simulation`. If there are no errors, `parseNetlist` must accept the IR, otherwise one `ir-invalid` error carries its message.
  - `compareNetlists`: both inputs already parsed. Compare title, element set by name ignoring case (kind, every numeric and string field, waveform, model name, control source), nodes through one growing bijection with `"0" ↔ "0"`, models by name (type, params), analyses and options with deep equality.
