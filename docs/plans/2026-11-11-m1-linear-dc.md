# M1 Linear DC Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `nodal-cli run` computes the DC operating point of any linear circuit (R, L, C, V, I, E, G, H, F) from netlist IR JSON. Topology errors name the offending elements. Results for L1–L4 match closed-form values, and L1–L3 also match committed ngspice goldens in CI.

**Architecture:** The netlist IR is defined twice, as serde types in `nodal-engine::ir` and as Zod schemas in `@nodal/schema`. One shared fixture set keeps the two definitions in agreement. The engine indexes the IR into a `Circuit`, rejects bad topologies, stamps each device into a dense real MNA system, and solves it through the `LinearSolver` trait (dense LU from faer). `nodal-cli` adds `run`, `export-spice` and `validate`; `validate` compares results with ngspice goldens produced by `validation/scripts/regen-goldens.mjs`.

**Tech Stack:** Rust 1.97.0, serde 1 + serde_json 1, faer 0.24, clap 4 (derive, CLI only); TypeScript 6.0, Zod 4, Vitest 5; ngspice (golden regeneration only, not in CI); Node 24 for scripts.

**Spec:** [`docs/ROADMAP.md`](../ROADMAP.md) §M1; [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md) §3, §4.1, §4.5; [`docs/reference/mna.md`](../reference/mna.md) §1–3, §6; [`docs/reference/numerical-methods.md`](../reference/numerical-methods.md) §4; [`docs/VALIDATION.md`](../VALIDATION.md) §2–4, §6; ADRs [0003](../adr/0003-linear-solver.md), [0008](../adr/0008-ngspice-golden-validation.md), [0009](../adr/0009-value-notation.md).

## Global Constraints

- Everything in `AGENTS.md` applies. In particular: `nodal-engine` has no I/O, clock or browser dependency; no `unwrap`, `expect` or `panic!` in library code paths of either crate; f64 in SI base units; English only.
- New Rust dependencies, and nothing else without a recorded ruling: `nodal-engine` gets `serde` 1 (derive), `serde_json` 1 and `faer` 0.24 (built without threads/rayon so it compiles for `wasm32-unknown-unknown`); `nodal-cli` gets `clap` 4 (derive) and `serde_json` 1.
- `nodal-wasm` keeps its M0 API (`engine_version` only). The gzipped `.wasm` stays under 1 MB; CI already enforces this.
- IR JSON uses camelCase keys. Element kinds are the SPICE letters `R L C V I E G H F`. Node `"0"` is ground.
- Sign conventions are those of `docs/reference/mna.md`: branch current positive from `n+` through the element to `n-`, so a source delivering power reports a negative current, as ngspice does.
- Result signal names: `V(<node>)` for node voltages and `I(<element>)` for branch currents (V, E, H, L only). Ground is never reported.
- Op comparison tolerance (VALIDATION §3): a sample passes if $|x - x_{ref}| \le 10^{-5}\,|x_{ref}| + a$, with $a = 10^{-8}$ V for `V(·)` and $a = 10^{-13}$ A for `I(·)`. Analytic tests use the same rule.
- Golden-run options (VALIDATION §2): `reltol=1e-6`, `vntol=1e-9`, `abstol=1e-15`, `chgtol=1e-18`. Every file in `validation/circuits/` carries them in `options`.
- Error messages list element and node names sorted in ascending ASCII order, comma-separated.
- No `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`.
- Commits: on `main`, Conventional Commits, author `TristanHottier <185231225+TristanHottier@users.noreply.github.com>`, no AI trailers. Run the humanizer skill on any doc prose before committing it.
- Out of scope: models, nodeset, Newton, sweeps, AC, transient, the wasm `run` entry point, the editor.

## Review Focus

1. **Names that differ only in case.** ngspice folds case, so `out` and `OUT`, or `R_a` and `R_A`, would silently merge in a golden run. They must be rejected by both schemas. Pinned by invalid fixtures in Task 2 and reused in Task 3.
2. **Branch-current signs.** A wrong sign passes every voltage check. Pinned by the analytic `I(V1)`, `I(E1)` and `I(H1)` assertions in Task 6 and Task 8.
3. **Singular by value, not by topology.** `E1 a 0 a 0 1` passes the graph checks but has no unique solution. It must give a clear error naming an unknown, never NaN. Pinned by `singular_vcvs_reports_unknown` in Task 6.
4. **Wide conductance range.** 1 mΩ next to 1 GΩ is a valid circuit and must not trip the singular-pivot check. Pinned by `wide_dynamic_range_is_not_singular` in Task 5.
5. **Exported numbers lose precision.** The SPICE deck must carry each value exactly (`0.1`, `1/3`), or goldens drift from the IR. Pinned by `export_round_trips_values` in Task 7.

**Interfaces:**
- Consumes: `Netlist`, `Element`, `Error` (Task 2).
- Produces:
  - `pub struct Circuit` with:
    - `node_names: Vec<String>`: unknown `i < node_count` is `V(node_names[i])`. Nodes are ordered by first appearance, scanning elements in order, `nodes` before `controlNodes`.

- Floating check (mna.md §6): union–find over DC edges, which are R, L, V, and the output pairs of E and H. Every node must reach `"0"`. On failure, return `Error::Floating`. `nodes` holds every unreachable node. `elements` holds every element with a terminal (`nodes`, not control ports) on one of them.
  - Display: `floating nodes with no DC path to ground: <nodes> (connected elements: <elements>)`.
- Loop check: add the V, E, H and L output edges one at a time to a second union–find. An edge whose ends are already joined closes a loop. Its members are that element plus the elements on the existing path between its ends, found by BFS over the edges added so far. Return `Error::SourceLoop` for the first loop found.
  - Display: `loop of voltage sources and inductors: <elements>`.

  - `pub trait LinearSolver { fn factor(&mut self, a: &DenseMatrix) -> Result<(), SolveError>; fn solve(&self, b: &mut [f64]) -> Result<(), SolveError>; }`
